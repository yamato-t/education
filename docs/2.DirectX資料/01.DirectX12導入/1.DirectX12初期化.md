# **DirectX12 初期化**

---

## **DirectX12の全体構造**

DirectX12は複数のオブジェクトが階層的に連携する設計となっている。  
これらの関係性は何らかのイメージで掴む方が把握しやすい。  

たとえば映画制作の役割で考えると

- プロデューサーが監督を選び、上映の手配をし  
- 監督が全体を統括し  
- 助監督が撮影指示を管理し  
- 撮影技師が指示に合わせて撮影を行い  
- 映写技師が劇場で再生し  
- 観客が映像を受け取る  

といった流れになる。  
このイメージをそのまま DirectX12 オブジェクトに照らし合わせると下記のようになる。  

- プロデューサー：DXGI ファクトリー
- 監督　　　　　：デバイス
- 助監督　　　　：コマンドキュー
- 撮影技師　　　：コマンドリスト
- 映写技師　　　：スワップチェーン
- 観客　　　　　：ディスプレイ

<span style ="color: red;">**DXGI**</span>（DirectX Graphics Infrastructure）は、  
GPU やディスプレイといった「表示まわりのハードウェア」を扱う Windows の基盤機能。  
DirectX12 本体とは別の仕組みとして用意されている。  

### **必要な DirectX12 オブジェクト**

| DirectX12 オブジェクト | 役割 | 主な機能 |
|--------------|------|----------------|
| DXGI ファクトリー | GPU情報の窓口 | アダプター列挙・スワップチェーン作成 |
| デバイス | GPU制御の中核 | リソース作成・管理 |
| コマンドキュー | 命令の実行管理 | GPU作業の順序制御 |
| コマンドリスト | 具体的な設定や作業 | 描画命令の記録 |
| スワップチェーン | 画面表示 | フレームバッファ管理 |

<span style ="color: red;">**これらのオブジェクトは相互依存関係にあり、正しい順序で初期化する必要がある**</span>。

---

## **DirectX12 初期化までの流れ**

下記の流れに沿って実装を進めていく。  

1. デバッグレイヤーの有効化（デバッグビルドのみ）
2. DXGI ファクトリー作成
3. アダプター選択と取得
4. DirectX12 デバイス作成
5. コマンドキューの作成
6. スワップチェーン作成

### **DirectX12 利用に必要なヘッダとライブラリ**

DirectX12 を利用する為には下記のヘッダのインクルードが必要になる。  

```c++
#include <d3d12.h>      // DirectX12 本体を利用する為のヘッダ
#include <dxgi1_4.h>    // Windows グラフィックス基盤機能を利用する為のヘッダ
```

もう一つ、DirectX12 は別ライブラリファイルとして用意されている為、  
ライブラリファイルとプログラムの紐付け（リンク）が必要になる。  

```c++
#pragma comment(lib, "d3d12.lib")   // DirectX12 の本体処理を利用する為に必要なライブラリ
#pragma comment(lib, "dxgi.lib")    // 画面への表示や管理を行う機能を利用する為のライブラリ
#pragma comment(lib, "dxguid.lib")  // DirectX12 オブジェクトを利用する為に必要なライブラリ
```

まずはこのヘッダのインクルードとライブラリの指定をコードに記述する。

## **デバッグレイヤーの有効化**

開発段階では、DirectX12 のデバッグレイヤーを有効にしておいた方が良い。  
これは「開発者向けの親切な先生」のような存在で、  
コードの問題点やパフォーマンスの改善点を詳細に教えてくれる。  

<span style ="color: red;">**デバッグレイヤーはデバイス作成より前に有効化する。**</span>  
デバイス作成後に有効化しても機能せず、作成済みのデバイスが使えなくなる。  
そのため初期化の流れの最初に呼び出す。  

```c++
void EnableDebugLayer()
{
#if defined(_DEBUG)
    // デバッグインターフェースを取得
    ID3D12Debug* debugController = nullptr;
    if (SUCCEEDED(D3D12GetDebugInterface(IID_PPV_ARGS(&debugController))))
    {
        // デバッグレイヤーを有効化
        debugController->EnableDebugLayer();

        // より詳細な検証を有効化（任意。動作は重くなる）
        ID3D12Debug1* debugController1 = nullptr;
        if (SUCCEEDED(debugController->QueryInterface(IID_PPV_ARGS(&debugController1))))
        {
            debugController1->SetEnableGPUBasedValidation(TRUE);
            debugController1->Release();    // 設定後は不要なので解放
        }

        debugController->Release();         // 設定後は不要なので解放
    }
#endif
}
```

有効化の設定は解放後も維持されるため、  
デバッグ用のオブジェクトは設定が済んだらすぐに解放してよい。  

### **デバッグレイヤーの効果**

- 解放漏れ（メモリリーク）の検出
- 不正なAPI使用の警告
- パフォーマンス問題の指摘
- リソース状態の不整合検出

デバッグレイヤーを有効にすると、Visual Studioの出力ウィンドウに詳細な情報が表示される。  
初心者はこの情報を頼りにコードを修正していく。

## **DXGI ファクトリーの作成**

DXGI ファクトリーは、  
システムに搭載された GPU の情報取得やスワップチェーンの作成を担当する。  
複数の GPU が搭載されたシステムでは、最適な GPU を選択する役割も果たす。  

```c++
IDXGIFactory4* CreateFactory()
{
    IDXGIFactory4* factory = nullptr;
    UINT createFactoryFlags = 0;

#if defined(_DEBUG)
    // デバッグビルドではデバッグフラグを設定
    createFactoryFlags = DXGI_CREATE_FACTORY_DEBUG;
#endif

    HRESULT hr = CreateDXGIFactory2(createFactoryFlags, IID_PPV_ARGS(&factory));
    if (FAILED(hr))
    {
        // エラーハンドリング：ファクトリー作成失敗
        OutputDebugStringA("Failed to create DXGI Factory\n");
        return nullptr;
    }

    return factory;
}
```

`OutputDebugStringA` は Visual Studio の出力ウィンドウに文字列を表示する関数。  
末尾の `A` は通常の文字列（`char`）を受け取る版であることを表し、  
プロジェクトの文字セット設定に関係なく `"..."` の文字列をそのまま渡せる。  

### **DXGI ファクトリーの主要機能**

DirectX による描画処理で頻繁に出てくるわけではないが、  

- GPU（アダプター）の列挙
- ディスプレイモードの取得
- スワップチェーンの作成
- フルスクリーン状態の管理

など「ディスプレイの情報」を取得しなければならない機会で必要になる。

## **アダプター選択と取得**

アダプターとは、システム内の GPU を表すオブジェクトとなる。  
統合 GPU、専用 GPU、ソフトウェアレンダラーなど、  
複数の選択肢から最適なものを選ぶ必要がある。  

```c++
IDXGIAdapter1* GetHardwareAdapter(IDXGIFactory4* factory)
{
    IDXGIAdapter1* adapter = nullptr;

    // ハードウェアアダプターを順番に検索
    for (UINT adapterIndex = 0; ; ++adapterIndex)
    {
        adapter = nullptr;
        if (DXGI_ERROR_NOT_FOUND == factory->EnumAdapters1(adapterIndex, &adapter))
        {
            break; // アダプターが見つからない場合は終了
        }

        // アダプター情報を取得
        DXGI_ADAPTER_DESC1 desc;
        adapter->GetDesc1(&desc);

        // ソフトウェアアダプターをスキップ
        if (desc.Flags & DXGI_ADAPTER_FLAG_SOFTWARE)
        {
            adapter->Release();
            continue;
        }

        // DirectX12対応テスト（最後の引数を nullptr にすると作成せず確認のみ行う）
        if (SUCCEEDED(D3D12CreateDevice(adapter, D3D_FEATURE_LEVEL_11_0, __uuidof(ID3D12Device), nullptr)))
        {
            return adapter; // 適切なアダプターを発見
        }

        adapter->Release();
    }

    return nullptr;
}
```

### **アダプター選択の判断基準**

複数のグラフィックボードを持つ PC の場合は複数のアダプターが見つかる。  
その中からどれを選ぶのかは、  

- ハードウェア支援の有無
- DirectX12 機能レベルの対応状況
- VRAM（Video RAM：GPU 専用のメモリ）の容量
- 性能指標

などの情報から検討する。

## **DirectX12 デバイス作成**

デバイスを作成する。  
全ての DirectX12 リソース（テクスチャ、バッファ、シェーダー等）はデバイスを通じて作成される。  

DirectX を利用して何かをしたい場合は、まずこれを作る必要がある。  

ハードウェアアダプターで作成できなかった場合は、  
<span style ="color: red;">**WARP**</span>（Windows Advanced Rasterization Platform）で作成を試みる。  
WARP は GPU の処理を CPU で代わりに行うソフトウェアアダプターで、  
動作は遅いが GPU がない環境でも DirectX12 を動かせる。  
WARP のアダプターは `EnumWarpAdapter` で取得する。  

```c++
ID3D12Device* CreateD3D12Device(IDXGIFactory4* factory, IDXGIAdapter1* adapter)
{
    ID3D12Device* device = nullptr;
    HRESULT hr = E_FAIL;

    // ハードウェアアダプターでデバイス作成を試行
    if (adapter != nullptr)
    {
        hr = D3D12CreateDevice(
            adapter,                    // 使用するアダプター
            D3D_FEATURE_LEVEL_11_0,     // 最小機能レベル
            IID_PPV_ARGS(&device)       // 作成されるデバイス
        );
    }

    if (FAILED(hr))
    {
        // フォールバック：WARP（ソフトウェアアダプター）を試行
        IDXGIAdapter* warpAdapter = nullptr;
        hr = factory->EnumWarpAdapter(IID_PPV_ARGS(&warpAdapter));
        if (SUCCEEDED(hr))
        {
            hr = D3D12CreateDevice(warpAdapter, D3D_FEATURE_LEVEL_11_0, IID_PPV_ARGS(&device));
            warpAdapter->Release();     // デバイス作成後は不要なので解放
        }

        if (FAILED(hr))
        {
            OutputDebugStringA("Failed to create D3D12 Device\n");
            return nullptr;
        }

        OutputDebugStringA("Using WARP adapter\n");
    }

    return device;
}
```

### **デバイス作成後に確認すべき項目**

上記のサンプルでは省略しているが、  
本格的なアプリケーションでは作成後に下記を確認する。  

- 機能レベルの対応確認
- 必要な機能の利用可能性チェック
- メモリ制限の把握

## **コマンドキューの作成**

続いてコマンドキューを用意する。  
CPU で作成した描画命令を受け取り、GPU に順番に実行させる役割を持つ。  

```c++
ID3D12CommandQueue* CreateCommandQueue(ID3D12Device* device)
{
    // コマンドキューの設定
    D3D12_COMMAND_QUEUE_DESC queueDesc = {};
    queueDesc.Type = D3D12_COMMAND_LIST_TYPE_DIRECT;    // 直接実行型
    queueDesc.Priority = D3D12_COMMAND_QUEUE_PRIORITY_NORMAL;  // 通常優先度
    queueDesc.Flags = D3D12_COMMAND_QUEUE_FLAG_NONE;    // 特別フラグなし
    queueDesc.NodeMask = 0;                             // 単一GPU使用

    ID3D12CommandQueue* commandQueue = nullptr;
    HRESULT hr = device->CreateCommandQueue(&queueDesc, IID_PPV_ARGS(&commandQueue));

    if (FAILED(hr))
    {
        OutputDebugStringA("Failed to create Command Queue\n");
        return nullptr;
    }

    // デバッグ用の名前設定（任意だが推奨）
    commandQueue->SetName(L"Main Command Queue");    // SetName は常にワイド文字列を受け取るため L を付ける

    return commandQueue;
}
```

### **コマンドキューの種類と用途**

- **DIRECT**: 汎用的な用途（基本これを最初に使う機会が多い）
- **COMPUTE**: 計算処理専用
- **COPY**: データ転送専用

「とりあえずポリゴンを描画する」を目標にしている為、  
まずは DIRECT でコマンドキューを作成しておく。

## **スワップチェーン作成**

スワップチェーンは GPU で描画した結果を画面に表示するためのバッファ管理を行う。  

描画先のバッファと表示中のバッファを分ける事で、  
描画途中の中途半端な画面が表示されてしまう問題を防ぐ。  
この仕組みを <span style ="color: red;">**ダブルバッファリング**</span> と呼ぶ。  

```c++
IDXGISwapChain3* CreateSwapChain(IDXGIFactory4* factory, ID3D12CommandQueue* commandQueue, HWND hwnd)
{
    // スワップチェーンの詳細設定
    DXGI_SWAP_CHAIN_DESC1 swapChainDesc = {};
    swapChainDesc.BufferCount = 2;                      // ダブルバッファリング
    swapChainDesc.Width = 1280;                         // 画面幅
    swapChainDesc.Height = 720;                         // 画面高
    swapChainDesc.Format = DXGI_FORMAT_R8G8B8A8_UNORM;  // ピクセルフォーマット
    swapChainDesc.BufferUsage = DXGI_USAGE_RENDER_TARGET_OUTPUT;  // レンダーターゲット用
    swapChainDesc.SwapEffect = DXGI_SWAP_EFFECT_FLIP_DISCARD;     // 高速切替
    swapChainDesc.SampleDesc.Count = 1;                 // マルチサンプリングなし

    IDXGISwapChain1* swapChain1 = nullptr;
    HRESULT hr = factory->CreateSwapChainForHwnd(
        commandQueue,      // コマンドキュー
        hwnd,              // ターゲットウィンドウ
        &swapChainDesc,    // 設定
        nullptr,           // フルスクリーン設定
        nullptr,           // 出力制限
        &swapChain1        // 作成されるスワップチェーン
    );

    if (FAILED(hr))
    {
        OutputDebugStringA("Failed to create Swap Chain\n");
        return nullptr;
    }

    // より高機能なインターフェースを取得
    IDXGISwapChain3* swapChain = nullptr;
    hr = swapChain1->QueryInterface(IID_PPV_ARGS(&swapChain));
    swapChain1->Release();

    if (FAILED(hr))
    {
        OutputDebugStringA("Failed to cast to SwapChain3\n");
        return nullptr;
    }

    return swapChain;
}
```

### **スワップチェーン設定の重要パラメータ**

- **BufferCount**: バッファ数（2または3を推奨）
- **Format**: 色深度とアルファチャンネル
- **SwapEffect**: バッファ切替方式
- **SampleDesc**: アンチエイリアシング設定

## **初期化処理のまとめ**

ここまでの関数を流れの順に呼び出すと、初期化処理は下記のようになる。  

```c++
EnableDebugLayer();                                         // 1. デバッグレイヤー
IDXGIFactory4* factory = CreateFactory();                   // 2. DXGI ファクトリー
IDXGIAdapter1* adapter = GetHardwareAdapter(factory);       // 3. アダプター
ID3D12Device* device = CreateD3D12Device(factory, adapter);  // 4. デバイス
ID3D12CommandQueue* commandQueue = CreateCommandQueue(device);              // 5. コマンドキュー
IDXGISwapChain3* swapChain = CreateSwapChain(factory, commandQueue, hwnd);  // 6. スワップチェーン
```

各オブジェクトが正常に作成されていれば、  
次の画面クリアやポリゴン描画に進むための基盤が整った状態となる。  
作成したオブジェクトの解放方法は「オブジェクトの解放」の資料で扱う。
