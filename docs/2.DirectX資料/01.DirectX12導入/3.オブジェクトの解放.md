# **オブジェクトの解放**

---

## **COM オブジェクト**

DirectX12 で作成したオブジェクトは、使い終わったら自分で解放する必要がある。  
ここでは解放の仕組みと正しい手順を確認する。  

### **COM オブジェクトとは**

DirectX12 で作成する `ID3D12Device`、`IDXGISwapChain`、`IDXGIAdapter`、  
`ID3D12CommandQueue`、`ID3D12Resource` など、  
**`ID3D` や `IDXGI` で始まる全てのオブジェクトは COM オブジェクトと呼ばれる。**  

<span style ="color: red;">**COM**</span>（Component Object Model）とは、  
Windows が採用しているオブジェクトの仕組み。  
異なる言語・環境からでも統一された方法でオブジェクトを扱えるようにするための規格となる。  
DirectX のオブジェクトもこの仕組みに則って設計されている。  

### **参照カウント**

COM オブジェクトは内部で <span style ="color: red;">**参照カウント**</span> を持っている。  
参照カウントは「このオブジェクトを今いくつの場所が使っているか」を表す数値となる。  

1. オブジェクトを作成すると参照カウントは 1 になる
2. `Release()` を呼ぶと参照カウントが 1 減る
3. 参照カウントがゼロになった時点でオブジェクトが破棄され、メモリが解放される

`Release()` を呼ばずにポインタが消えると、メモリリークが発生する。  
<span style ="color: red;">**作成した COM オブジェクトは必ず Release すること。**</span>  

---

## **解放の手順**

### **GPU の処理完了を待つ**

GPU は CPU とは別に動いているため、  
CPU 側の処理が終わっても GPU がまだコマンドを実行している場合がある。  
<span style ="color: red;">**GPU が使用中のオブジェクトを解放してはならない。**</span>  
解放の前に、「画面クリア」の資料で扱ったフェンスを使って GPU の処理完了を待つ。  

### **解放の例**

「DirectX12 初期化」と「画面クリア」で作成したオブジェクトを解放する例を示す。  
以降の章でオブジェクトが増えた場合も、同じ考え方で解放処理を追加していく。  

```c++
// GPU の処理完了をフェンスで待ってから解放する

// 使い終わったオブジェクトを解放する
// Release() を呼ぶと参照カウントが減り、0 になった時点でメモリが解放される
CloseHandle(fenceEvent);        // イベントは COM ではないため CloseHandle で閉じる
fence->Release();
commandList->Release();
for (int i = 0; i < 2; i++)
{
    commandAllocators[i]->Release();
    renderTargets[i]->Release();
}
rtvHeap->Release();
swapChain->Release();
commandQueue->Release();
device->Release();
adapter->Release();
factory->Release();
```

### **解放の順番**

<span style ="color: red;">**作成した順序と逆順に Release するのが基本原則。**</span>  
後から作ったオブジェクトは、先に作ったオブジェクトを利用していることが多い。  
利用している側から先に解放することで、依存関係による参照が残る事を防ぐ。  

```c++
// 作成順：factory → adapter → device → commandQueue → swapChain → ... → fence
// 解放順：fence → ... → swapChain → commandQueue → device → adapter → factory
```

### **デバッグレイヤーで確認する**

解放漏れがあると、デバッグビルドの終了時にデバッグレイヤーが  
以下のような警告を出力ウィンドウに表示する（表示内容は環境により異なる）。  

```
D3D12 WARNING: Live ID3D12Device at 0x..., Refcount: 1
```

この警告が出た場合は、該当オブジェクトの `Release()` 漏れを疑うこと。

## **ComPtr による自動解放**

`Release()` の呼び忘れを防ぐ仕組みとして、**ComPtr** が用意されている。  
ComPtr は COM オブジェクト専用のスマートポインタで、  
スコープを抜けた際に自動で `Release()` を呼んでくれる。  
`#include <wrl/client.h>` で利用でき、`Microsoft::WRL::ComPtr<T>` として使用する。  

```c++
#include <wrl/client.h>
using Microsoft::WRL::ComPtr;

// ComPtr で宣言すると、スコープを抜けた時に自動で Release される
ComPtr<ID3D12Device> device;
ComPtr<ID3D12CommandQueue> commandQueue;

// 作成方法は生ポインタと同じ（IID_PPV_ARGS に渡せる）
D3D12CreateDevice(adapter, D3D_FEATURE_LEVEL_11_0, IID_PPV_ARGS(&device));

// 生ポインタとして取り出す場合は .Get() を使う
someFunction(device.Get());

// Release を明示的に呼ぶ必要はない（スコープ終了時に自動解放）
```

<span style ="color: red;">**実際の開発では ComPtr の利用が推奨される。**</span>  

ただし、本資料のサンプルコードでは「各オブジェクトが生ポインタである」ことを明示し、  
生ポインタと `Release()` の関係を理解しやすくするため、あえて生ポインタで統一している。  
実装の際には ComPtr への置き換えを検討してほしい。
