# **コマンドパターン**

---

## **コマンドパターンとは**

コマンドパターンとは、「操作」そのものをオブジェクトとして表現する  
設計パターン。  

通常は関数を直接呼び出して終わりだが、  
コマンドパターンでは操作をクラスにカプセル化することで、  
操作の記録・取り消し・再実行・遅延実行が可能になる。  

ゲーム開発では入力バッファ・Undo/Redo・  
リプレイ機能の実装に広く使われる。  

---

## **なぜコマンドパターンが必要か**

### **直接呼び出しの限界**

入力に応じてキャラクターを操作する処理を素直に書くと次のようになる。  

```c++
void InputHandler::update()
{
    if (input.isPressed(KEY_UP))    player.moveForward();
    if (input.isPressed(KEY_DOWN))  player.moveBack();
    if (input.isPressed(KEY_A))     player.jump();
    if (input.isPressed(KEY_B))     player.attack();
}
```

この書き方では以下の要件に対応できない。  

- キーコンフィグ（ボタン割り当ての変更）
- 操作の undo（一手前に戻る）
- リプレイ（過去の操作を再現する）
- AI による操作（プレイヤーと同じ行動系統を使い回す）

いずれも「操作をデータとして保存・再利用する」必要があるが、  
直接呼び出しではそれができない。  

---

## **コマンドパターンの仕組み**

### **二つの要素**

- <span style ="color: red;">**Command 基底クラス**</span>
    - すべての操作に共通する `execute()` を定義する。  
- <span style ="color: red;">**具体的な Command クラス**</span>
    - 「移動」「ジャンプ」「攻撃」など、各操作をクラスとして実装。  
    - 実行に必要な情報をメンバ変数に保持する。  
- <span style ="color: red;">**キーとコマンドを紐付けするクラス**</span>
    - 各キーとコマンドを紐付ける為のクラス
    - このクラスを経由して各コマンドの実行処理を呼び出す

## **実装例**

基本的なキーコンフィグの実装を例で挙げる。  
プレイヤー、プレイヤー操作のコマンド、コマンドとキーの紐付けの三つの構成で実装する。

### **コマンドで操作するクラス**

まずはコマンドで操作する対象のプレイヤーを用意する。  
プレイヤーには行動の関数を用意する。

```c++
// プレイヤークラス
class Player {
public:
    void moveForward() { /* 前方に移動する処理 */ }
    void jump(float power) { /* ジャンプする処理 */ }
};
```

### **Command 基底クラス**

次にプレイヤー操作のコマンドクラスを用意する。  

```c++
// コマンド基底クラス
class Command {
public:
    virtual ~Command() {}
    // コマンドを実行するための純粋仮想関数
    virtual void execute(Player& player) = 0;
};
```

### **具体的な Command クラス**

コマンド基底クラスを用意し、それを継承した具体的なコマンドクラスを実装する。  
オーバーライドした仮想関数内で、プレイヤーの行動関数を呼び出す。

```c++
// 前方に移動するコマンド
class MoveForwardCommand : public Command {
public:
    // プレイヤーを前方に移動させる処理を実装
    void execute(Player& player) override {
        player.moveForward();
    }
};

// ジャンプするコマンド
class JumpCommand : public Command {
public:
    // プレイヤーをジャンプさせる処理を実装
    void execute(Player& player) override {
        player.jump(jumpPower_);
    }

private:
    float jumpPower_ = 1.0f; // ジャンプ力
};
```

### **キーとコマンドを紐付けするクラス**

最後にコマンドとキーの紐付けを用意する。  
まずはキーとコマンドクラスを紐付ける。  
更新処理の中で、キーに紐づいたコマンドの execute 関数を呼び出す。

```c++
// コマンドの紐付けを制御するクラス
class InputHandler {
public:
    InputHandler(std::shared_ptr<Player> player)
        : player_(player) {}

    // キーとコマンドを紐付ける（キーコンフィグ）
    void setCommand(int key, Command* command) {
        bindings_[key].reset(command);
    }

    // 入力を監視し、対応するコマンドを実行する
    void update() {
        for (auto& [key, command] : bindings_) {
            if (input.isPressed(key)) {
                command->execute(*player_);
            }
        }
    }

private:
    std::map<int, std::unique_ptr<Command>> bindings_{};  // キーとコマンドの紐付け
    std::shared_ptr<Player>                 player_{};    // プレイヤーへの参照
};
```

これらを下記のように利用する。

```c++
// プレイヤーの作成
auto player = std::make_shared<Player>();

// ボタン割り当てを自由に差し替えられる
InputHandler handler(player);
handler.setCommand(KEY_UP, new MoveForwardCommand());
handler.setCommand(KEY_A, new JumpCommand());

// 入力を監視し、対応するコマンドを実行
handler.update();  

// キーコンフィグの変更も差し替えるだけ
// Aキーがジャンプから前方移動に変更される
handler.setCommand(KEY_A, new MoveForwardCommand());

// キーコンフィグを反映したコマンドが実行される
handler.update();  
```

## **直接呼び出しとの比較**

| 比較項目 | 直接呼び出し | コマンドパターン |
|---|---|---|
| キーコンフィグ | 条件分岐を書き換える必要がある | コマンドを差し替えるだけ |
| Undo / Redo | 別途状態管理が必要で複雑になる | 履歴スタックと `undo()` で実現 |
| リプレイ | 操作を記録する仕組みがない | コマンドリストを再生するだけ |
| AI 操作 | プレイヤーとは別の仕組みが必要 | 同じコマンドを AI が発行できる |

## **その他**

### **コマンドクラスが増えすぎる場合**

操作の種類が多いと、コマンドクラスの数も比例して増える。  

例えば「押した瞬間」「離した瞬間」「押し続けている間」など、  
同じキーでもコマンドの実行手段が色々必要になった場合は、  
ラムダ式でシンプルに書く方法もあり。  

```c++
// アクションコマンド
class ActionCommand : public Command
{
public:
    ActionCommand(std::function<void()> hold,
                  std::function<void()> release)
        : holdFunc_(hold), releaseFunc_(release) {}

    void hold()     override { holdFunc_(); }
    void release()  override { releaseFunc_(); }

private:
    std::function<void()> holdFunc_{};
    std::function<void()> releaseFunc_{};
};
```

```c++
// 個別クラスを作らずにその場で定義できる
auto cmd = ActionCommand(
    [&]() { player.dash(); },
    [&]() { player.jump(); });

cmd.hold();     // ダッシュする
cmd.release();  // ジャンプする
```

## **まとめ**

| ポイント | 内容 |
|---|---|
| 目的 | 操作をオブジェクト化し、記録・取り消し・再実行を可能にする |
| 構成要素 | Command インターフェース ＋ 具体コマンド ＋ 履歴管理 |
| 主な用途 | キーコンフィグ・Undo/Redo・リプレイ・AI操作 |
| 発展形 | ラムダ式との組み合わせでクラス数を削減できる |

コマンドパターンの本質は、  
<span style ="color: red;">**「操作を呼び出しから切り離し、データとして扱えるようにする」**</span>こと。  
「後から操作を再利用したい」という要件が出てきたとき、  
導入を検討するパターン。
